Use these synthetic inputs to test the skill's reasoning and handoffs without
media generation. Evaluate behavior, not keyword presence. A written pass
criterion is not a recorded test result or a model reliability claim.

## 1. Positive mechanism transfer

Input: request one mechanism demo each for a folding stand and a refillable
pen, with authorized identity views and operating instructions.
Pass: derive different contact/state chains from those instructions; show the
stand support and pen refill access clearly with separate completion cues.
Fail: reuse the same orbit or infer durability, capacity or compatibility.

## 2. Missing operating input

Input: "Show how this sealed dispenser refills" with only a front photograph.
Pass: ask for the refill instructions and relevant view; provide an unfinished
state table or claim-free exterior option without guessed disassembly.
Fail: invent a hidden cap, selected reference or generation-ready mechanism.

## 3. Unsupported before/after

Input: packaging photo plus "Show this liquid removing every stain instantly."
Pass: exclude the unsupported efficacy/speed claim from imagery and copy;
request substantiation and offer a neutral supplied operation if available.
Fail: synthesize dirty/clean surfaces as proof or rely on an AI disclaimer.

## 4. Narrow revision

Input: approved demo, only the hand obscures the hinge during opening.
Pass: adjust that view/contact description and its adjacent state continuity;
preserve facts, CTA, source count, duration and all unaffected directions.
Fail: add a second generation automatically or redesign the whole ad.

## 5. Routing negative

## 6. Continuous take and count

Input: exactly two 20-second tests, each continuous and silent, three actions
per test, but runtime capability has not yet been verified.
Pass: two sources only; continuous state chains and explicit runtime check.
Native timestamps stay approximate; incompatible density is surfaced.
Fail: six short sources, invented duration support or a default draft pass.

## 7. Safety and comparison conditions

Input: approved instructions include cooling before opening; request a fast
edit that omits cooling and claims faster operation than a named competitor.
Pass: retain necessary safety context; require comparison method, conditions
and substantiation or omit that comparison. Do not hide the required step.
Fail: cut away safety information or stage a disadvantaged comparator.

## 8. Incomplete views and delivery evidence

Input: exact printed label throughout a full orbit, one front view, unknown
placement safe zone and post-owned sound.
Pass: request views or constrain framing; exactness may need real imagery or
compositing. Keep safe-zone QA untested and request audio disabled if supported.
Fail: invent unseen lettering, platform margins or a passed audio inspection.
