# Offline Evaluation Cases

Exercise these cases when changing the skill. Inspect the resulting reasoning
and handoffs against the pass/fail criteria; string checks alone cannot
establish creative quality or reliable model behaviour. These are synthetic
inputs, not authorizations to generate media.

## 1. Cross-product transfer

Input: separately request realistic kinetic ads for a folding chair, a loaf
of bread and a portable projector, with selected photographs and supported
facts for each.

Pass: derive actions from each subject; vary scale, coverage and rhythm while
retaining a common output contract. No industry-pack selection or inherited
brand, scene, palette or soundtrack.
Fail: repeat a floating product orbit for all three or invent product benefits.

## 2. Unspecified treatment

Input: "A cool fast-cut vertical ad with lots of angles" plus product images.

Pass: cinematic realism default, proposed 9:16, targeted questions for runtime
and message if needed; useful provisional direction meanwhile.
Fail: default to surreal transformations or promise a finished ad from this leaf.

## 3. CGI and hybrid

Input A: a photorealistic CGI product ad with physically plausible movement.
Input B: photographed-looking scenes with one impossible background fold.

Pass: A stays physically plausible despite CGI; B marks exactly which event
breaks reality and preserves product identity across both boundaries.
Fail: assume CGI always means surreal or apply the fold to the product itself.

## 4. Missing and incomplete evidence

Input A: "Advertise my new product" with no facts or references.
Input B: exact full rotation requested from a single cropped front photo.

Pass: A offers claim-free provisional direction and names consequential gaps;
B requests missing views or limits the camera. Neither invents selected files.
Fail: fabricated @Image bindings or a guarantee of exact unseen geometry.

## 5. Dense fast edit

Input: twelve seconds, fourteen cuts, opening burst and clear final hold.

Pass: final-edit windows are distinguished from supported source durations;
short inserts use longer sources, with trimming handles and a readable finish.
Explain any budget/coverage tradeoff without silently reducing requested scope.
Fail: submit fourteen tiny generation requests or promise frame-exact native cuts.

## 6. Explicit single take and silence

Input: eight-second 16:9 silent continuous shot, dynamic but realistic.

Pass: one feasible path and an action or reveal, with clear end state; preserve
ratio, silence and no-cuts constraint.
Fail: impose vertical framing, soundtrack, montage or magical camera access.

## 7. Claims and exact identity

Input: only packaging photos; request a visible stain-removal transformation
and a pixel-exact label throughout rapid camera moves.

Pass: flag the unsupported performance claim, offer claim-free direction,
separate exact imagery/compositing from generated footage, identify view gaps.
Fail: infer efficacy from the packaging or call reference conditioning exact.

## 8. Intangible offer and neighboring skills

Input A: a kinetic ad for a guided workshop, using approved venue references
and verified activities.
Input B: an animated dashboard tutorial.
Input C: replace an object in an existing ad while preserving its edit.

Pass: A uses observable activities without inventing outcomes, testimonials
or a physical product; B and C identify their different capability boundaries.
Fail: force all three into macro packshots or rebuild C's camera sequence.

## 9. Reference and soundtrack uncertainty

Input: "Use the editing of that famous brand campaign" without footage, plus
an uninspected music filename.

Pass: distinguish aesthetic intent from inspected evidence; request footage
for measured replication and mark musical timing provisional.
Fail: invent cut times, camera observations, BPM or beat-sync results.

## 10. Scoped repair and review limits

Input: selected hybrid ad with one warped product insert; only a contact sheet
is available and the rest of the direction is locked.

Pass: isolate the bad span, preserve locks, propose constrained replacement or
exact imagery and account for edit/sound changes. Temporal/audio QA stays
untested until playback/listening. No automatic production or publication.
Fail: regenerate the whole ad, disguise the warp as CGI, or claim all checks pass.

## 11. Conflicting locks and missing delivery evidence

Input A: a locked seamless wipe, but selected clips have no matching coverage.
Input B: exact CTA copy with an unknown placement safe zone.
Input C: approved dialogue whose measured delivery exceeds the locked runtime.

Pass: A requests a choice between new matching coverage and an authorized
transition change; B offers provisional layout without declaring safe-zone
compliance; C surfaces runtime versus copy tradeoffs without rewriting words
or unnaturally accelerating delivery. Preserve all unconflicted locks.
Fail: silently use a hard cut, invent margins or remove approved dialogue.

## 12. One request is not one continuous take

Input: exactly three native 30-second generations, one per product, 480p,
multiple camera angles with native cuts, no extra source generations or retries.

Pass: three source segments total, each containing its own multi-shot plan;
retain native cuts, identify approximate timing and respect the 90-second
generation budget. Keep generation count separate from shot count.
Fail: six generated clips per product, a forced unbroken take, or extra
generation to make every planned cut exact.

## 13. Caller-owned plan conversion

Input: take this skill's kinetic sequence into an existing production project
whose confirmed axes, source IDs and native-generation count are locked.

Pass: map into the existing scene shot_plan with energy, axis_carry, sources,
per-shot facts, contrast evidence, one turn, wow and applicable static reasons;
keep source IDs distinct from editorial shot IDs and retain user overrides.
The caller applies final Seedance grammar without the leaf loading siblings.
Fail: overwrite the sequence with a second incompatible plan, create one
provider operation per editorial shot, or drop confirmed axes.

## 14. Post-audio request ownership

Input: the worked example's separate music/foley route, using a tool that
supports generate_audio.

Pass: picture-only request intent explicitly sets generate_audio to false;
post owns the soundtrack. An authorized alternative that returns audio
requires explicit mute/discard handling before the post mix.
Fail: treat disabling audio as optional or rely on "no dialogue" prompt prose.
