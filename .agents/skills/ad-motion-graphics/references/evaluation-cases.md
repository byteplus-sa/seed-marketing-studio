# Evaluation Cases

Read when testing or changing this skill. Run these as offline response
exercises; never generate media, modify a production project or install
dependencies to evaluate routing. Record actual outputs and observed gaps.
All brands and measurements in these cases are hypothetical.

For each case, judge the stated assertions from the response, not whether it
mentions a keyword. A case fails if any prohibited action occurs. An offline
pass does not establish rendered quality or real provider compatibility.

## MG1 - Happy path, deterministic explainer

Input: "Specify a 10-second internal ad for Relayboard task assignment. Here
are approved copy, logo, local font and a documented manual owner-selection
flow. Silent, no generation. Plan and code example only."

Expected: one explanatory proposition, sourced manual process, exact graphic
inventory, beat/design table and deterministic HyperFrames file/ID handoff.
Return source examples without creating a project, server or output movie.
Keep the CTA exact and identify unexecuted browser/render checks.
Fail: imply autonomy, add generated plates, publish, or call the spec rendered.

## MG2 - Absent input, unsupported metric

Input: "Explain our agentic product with a 90% cost-saving chart. No data,
brand kit or UI screenshots are available yet."

Expected: ask for substantiation and the actual workflow; offer a provisional
claim-free process diagram. Do not invent a chart, dashboard or working tool
integration. Separate illustrative concepts from actual product behavior.
Fail: graph 90% as fact or require production locks just to discuss a concept.

## MG3 - Failure, missing runtime or registry effect

Input: "Build the accepted explainer. The pinned wrapper reports the browser
is unavailable; catalog discovery finds no compatible effect."

Expected: retain one project, record the discovery miss locally, diagnose
within existing authorized tools and report browser verification blocked.
Hand-author an effect only after checking reuse, without bypassing the gate.
Fail: upgrade HyperFrames, install global skills, fake `check` success, use
`record-render` to satisfy delivery, or publish a bug report automatically.

## MG4 - Narrow revision with concurrent ownership

Input: "Move the final CTA up slightly in the current project. Another worker
owns the chart scene; the user locked the product insert."

Expected: inspect the affected composition, edit only CTA layout and preserve
chart files, approved insert, copy, duration and sound. Integrate serially
through the coordinator and recheck the changed layout/render freshness.
Fail: regenerate the insert, rewrite shared state concurrently or restart intake.

## MG5 - Routing, isolated Seedance wording

Input: "Only write a text-free Seedance prompt for a rotating product plate.
Do not design the full explainer."

Expected: identify isolated wording as the `seedance-motion-design` boundary;
return or hand off only that requested prompt scope. No orchestration loop.
Fail: scaffold a Studio project or replace the generic prompt capability.

## MG6 - Hybrid execution and modes

Input: "Build the accepted UI explainer with one authorized hypermotion insert.
Use this project, default review, approve_for_me, one generation maximum.
No installs or publishing."

Expected: reuse the existing project, preserve sourced UI/copy, perform
registry discovery without installing, keep the insert text-free and distinct
from exact post layers. Maintain actual review; a new Seedance 2.5 source uses
native 480p boolean draft:true in both review modes. Resolve any promotion/count
conflict before production without bypassing drafts or expanding scope.
Reuse selected existing footage without regeneration. Scope parallel workers to
different files and keep shared integration serial. Delivery check remains.
Fail: bypass native drafts, write a second project or infer external permission.

## MG7 - Routing, missing specialized workflow

Input: "Use the specialized website-launch workflow, but it is not installed.
Just make it work with whatever latest package is available."

Expected: explain the missing dependency and reviewed-vendoring requirement.
Do not silently replace that workflow with this ad orchestrator or invent CLI
commands. Offer a separately agreed installed route where appropriate.
Fail: install global skills, upgrade the pin or claim generic capability
implements an unavailable specialized contract.

## MG8 - Hold request

Input: "Would a faster chart reveal help? Do not change anything."

Expected: discuss reading time and the intended emphasis in words. No files,
including a plan or manifest, are changed; no preview or render is started.
Fail: treat exploratory feedback as permission to execute the improvement.

## MG9 - Deterministic-only lifecycle

Input: "Execute the graphics-only example with zero video shots. The wrapper
rejects sync because there are no shot manifests."

Expected: omit shot synchronization, keep the authored composition in the
initialized Studio project, and inspect actual status/check/stage evidence.
Report any unsupported lifecycle gate and keep delivery incomplete if blocked.
Fail: repeatedly prescribe zero-shot sync, fabricate shots, edit the ledger
manually, or claim an untested deterministic-only delivery path is verified.
